# Redesign decisions: cashier UI

Status: decided 2026-10-16. Scope: `public/` only (`www/` is generated by `scripts/build-android.mjs`, never edit it). Mode: Operate. One cashier, one Android tablet, greasy hands, bright counter light, offline. Every rule below is firm; implementers do not pick alternatives.

## 1. Design direction

1. **Feel: "kraft box + hot sauce".** Warm kraft-paper neutrals, one loud buffalo-orange for money and the next action, near-black ink for numbers. Flat, high-contrast, no gradients, no glass, no decorative shadows beyond one soft lift. The total and the card number are the heroes; everything else is quiet.
2. **Palette tokens (light is default; counter light is bright).**
   Light: `--bg #F6EFE3` `--surface #FFFBF4` `--raised #FFFFFF` `--ink #1E130C` `--muted #6B5546` `--line #E3D3BC` `--primary #C8380A` `--on-primary #FFFFFF` `--primary-soft #FBE2D3` `--honey #E9A21F` `--ok #1F6B43` `--ok-soft #D9EEDF` `--bad #A8231B` `--bad-soft #F8DEDA` `--info #17598F` `--info-soft #DBEAFB` `--warn #7A4A00` `--warn-soft #FDECC4` `--c1 #C8380A` `--c2 #1E6AA8` `--grid #E6D6BF` `--scrim #1A0D0599`.
   Dark: `--bg #14100C` `--surface #1F1813` `--raised #2A211A` `--ink #F7EBDC` `--muted #B9A28E` `--line #3B2E22` `--primary #FF7A3D` `--on-primary #1A0A02` `--primary-soft #4A2210` `--honey #F2B544` `--ok #5CCB8E` `--ok-soft #15372A` `--bad #FF8A80` `--bad-soft #48201B` `--info #8CC9F2` `--info-soft #153653` `--warn #F4C46A` `--warn-soft #4A3510` `--c1 #F0692E` `--c2 #3A9DDB` `--grid #3A2B1F` `--scrim #000000B3`.
   Contrast checked: white on `#C8380A` 5.2:1, `#6B5546` on `#F6EFE3` 6.1:1, white on `#1F6B43` 6.5:1, `#1A0A02` on `#FF7A3D` 7.5:1.
3. **Type: system stack only, no bundled or network font.** `--font: system-ui, Roboto, "Segoe UI", -apple-system, sans-serif` (Roboto on the tablet). Weights 600 body, 800 numbers and labels. All money uses `.num` (tabular figures). Scale: `--t-xs 13px` `--t-sm 15px` `--t-md 17px` `--t-lg 22px` `--t-xl 40px` (live total) `--t-2xl 56px` (pay total, change due). Uppercase only for small labels (`--t-xs`, letter-spacing .08em).
4. **Spacing scale (4px base):** `--s1 4px` `--s2 8px` `--s3 12px` `--s4 16px` `--s5 24px` `--s6 32px`. No other spacing values in new or touched rules.
5. **Radius scale:** `--r-sm 12px` (keys, inputs, steppers, seg buttons), `--r 16px` (tiles, boxes, cards, buttons), `--r-lg 24px` (sheet top corners), `--r-pill 999px` (tabs, chips, pills). One shadow token `--shadow` kept as is.

## 2. Ergonomics rules

- **Touch targets.** Absolute minimum 48x48px for anything tappable (tabs, chips, steppers, switches' hit area). 56px height for in-flow primary controls (keypad keys, quick-cash, seg buttons, `.btn`, card-number buttons). 64px for Charge/Confirm and the queue Done button. Gap between adjacent targets at least `--s2` (8px).
- **Thumb/hand zone.** The one action that moves the sale forward always sits at the bottom-right of the screen.
  - Portrait, order and pay views: bottom bar reads `[Cancel] .....spacer..... [Back] [Charge ₱174]`. Brand text is hidden in these views. Charge/Confirm is `.nbtn.wide` (min 160px wide, 64px tall) and shows the amount. Cancel sits alone at the far left, at least 24px from Back.
  - Landscape (>=900px): on home/order the `.live` total strip becomes a sticky dock at the **bottom** of `#main` (total left, Charge right). In the left rail during order/pay, Cancel stays at the top of the rail and Confirm is pushed to the bottom of the rail (`margin-top: auto`), so it is under the resting hand.
- **Glanceable total.** The running total is always visible while building an order: 40px/800 in the `.live` strip (top in portrait, bottom dock in landscape), 56px on the pay screen, 56px change due. The visible number is `aria-hidden`; a visually hidden `aria-live="polite"` span carries the final total only (so the roll-up does not spam screen readers).
- **Tap feedback.** Every button, tile, key and card scales to .96 on press (section 3, "tile press"), and every add shows a count bump. No hover-only states. Keep `touch-action: manipulation` (kills the 300ms delay) and add one passive `touchstart` no-op listener so `:active` fires reliably on touch.
- **Mis-tap protection.**
  - Cancel order with items in the cart: clear immediately and show the existing undo-toast pattern ("Order cancelled", Undo, 5s) that restores cart and payment state. Empty cart: just go home.
  - Queue Done: keep the two-tap arm (3.5s), but the armed state is a class `.donebtn.armed` (solid `--ok` fill, label "Tap again" under it), not an inline style.
  - Void: keep reason picker + 5s undo (already correct). Restore: keep the confirm sheet.
  - Destructive controls never sit adjacent to the primary action, and are never placed in the bottom-right slot.

## 3. Motion spec

Budget: nothing over 300ms total (delay + duration), transform and opacity only in CSS, no animation ever blocks input (elements leaving get `pointer-events: none`; nothing awaits an animation before accepting the next tap). All motion lives in `public/motion.css`. Tokens (in `style.css` `:root`):
`--ease-out: cubic-bezier(.2, .8, .2, 1)` `--ease-in: cubic-bezier(.4, 0, 1, 1)` `--ease-pop: cubic-bezier(.34, 1.56, .64, 1)` `--ease-std: cubic-bezier(.4, 0, .2, 1)`.

| # | Animation | Trigger hook (class / JS) | Duration | Easing | Property | prefers-reduced-motion |
|---|---|---|---|---|---|---|
| 1 | Tile / button press | `:active` on `.tile, .btn, .nbtn, .key, .card, .step button, .seg button, .quick button, .tab, .charge, .donebtn` | 80ms in, 120ms out | `--ease-out` | `transform: scale(.96)` | no transition, no scale; press shown by the existing color/border state only |
| 2 | Add-to-cart count bump | `.is-bump` on the tile's `.q` badge and stepper `.v` (set by app.js for the one item just changed) | 160ms | `--ease-pop` | `transform: scale(1.25 -> 1)` | none (number just changes) |
| 3 | Total roll-up | JS `rollTo(el, from, to)` in app.js, rAF tween of `textContent`, plus `.is-bump` on `.live .amt` | 180ms | ease-out cubic in JS (`1 - (1-t)^3`); pulse uses `--ease-out` scale 1.06 -> 1 | text content (tabular figures, no reflow) + `transform` | set final value instantly, no pulse |
| 4 | Sheet slide-up / dismiss | `.scrim` + `.sheet` on insert; `.scrim.is-closing` on dismiss | in 220ms (scrim fade 160ms); out 160ms | in `--ease-out`; out `--ease-in` | sheet `transform: translateY(100% -> 0)`; scrim `opacity` | in: none; out: element removed immediately |
| 5 | Order-finish confirmation | `.sheet.is-done .change .amt` and `.is-done h2` | 240ms, 60ms delay on amount | `--ease-pop` | amount `transform: scale(.85 -> 1)` + `opacity 0 -> 1`; h2 `opacity` | everything shown statically |
| 6 | Queue item enter | `.order.is-enter` (app.js marks the order just created) | 200ms | `--ease-out` | `transform: translateY(-8px -> 0)` + `opacity 0 -> 1` | none |
| 7 | Queue item exit (Done) | `.order.is-leaving`; app.js fires the API call at the same moment and re-renders after `Promise.all([api, wait(180)])` | 180ms | `--ease-in` | `transform: translateX(24px) scale(.98)` + `opacity 1 -> 0` | `wait(0)`; element just disappears on re-render |
| 8 | Tab switch (category, queue filter, ledger tab) | `.is-swap` on the content container whose tab changed (`.grid` for category, `.orders` for queue filter, `#lbody` for ledger) | 140ms | `--ease-std` | `opacity 0 -> 1` + `transform: translateY(4px -> 0)` | none |
| 9 | Party-pack add | on "Add pack": `.is-bump` on the Done button's count `<b class="pk">` and the Add button | 160ms | `--ease-pop` | count `transform: scale(1.25 -> 1)`; Add button `transform: scale(.96 -> 1)` | none |
| 10 | Toast in | `.toast` on insert | 160ms | `--ease-out` | `transform: translate(-50%, 12px -> -50%, 0)` + `opacity` | none |
| 11 | Switch thumb | `.switch::after` | 160ms | `--ease-out` | `transform` (existing) | none |

Reduced motion is one block at the end of `motion.css`: `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation: none !important; transition: none !important; } }`, plus app.js reads `const calm = matchMedia('(prefers-reduced-motion: reduce)')` and uses `calm.matches` to skip the roll-up tween and set exit wait to 0. Because app.js re-renders with `innerHTML`, a `.is-*` class must be placed only on the one element that changed in that render and cleared from state right after rendering, or every badge replays.

- Total roll-up: module-level `let shownTotal = 0, rollRaf`; after `renderOrder` writes markup, call `rollTo(el, shownTotal, t)` (180ms rAF, ease-out cubic, writes `peso(Math.round(v))`, cancels prior rAF), add `is-bump` to `.live .amt` when the total changed; `calm.matches` -> set instantly.
